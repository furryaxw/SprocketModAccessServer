# 前端框架与实现基准

## 目标与边界

前端包含登录、会话、工作区、授权快照、资源页面和业务操作。
本文档描述 `admin-ui/src/` 的实现基准。

## 目录职责

- `src/layouts/`：应用网格壳，包括工作区切换、侧栏、页头、内容区和页脚。
- `src/components/`：跨页面复用的结构组件与状态组件。
- `src/ui/`：跨页面复用的基础交互组件，例如按钮、输入框、表格、列表、弹窗和通知。
- `src/composables/`：请求状态、通知调用和无副作用的算法工具。
- `src/i18n/`：中文主语言与英文资源，以及语言切换入口。
- `src/theme/`：颜色、间距、排版、圆角、阴影和主题状态。
- `src/pages/`：业务页面，负责组合共享组件、调用资源操作并根据授权快照
  投影页面和操作。
- `src/router/`：框架路由配置。

## 页面壳与网格

页面壳采用 CSS Grid，不用绝对定位堆叠主要结构，固定为四区：

1. 左上 1 区：Logo 与侧栏折叠按钮。
2. 右上 2 区：固定页面 Header，显示页面标题、当前工作区和全局入口。
3. 左下 3 区：工作区下拉列表与当前页面导航。
4. 右下 4 区：主内容区，页脚也只属于此区。

1、2、3 区采用直角贴边固定结构；3 区页面导航独立纵向滚动，4 区主内容独立纵向滚动，1、2 区不参与滚动。移动端默认隐藏 1、3 区，只显示 2、4 区；2 区左侧提供展开按钮，点击后同时展开 1 区并打开 3 区侧栏抽屉。抽屉与主内容并列覆盖，不挤压 2 区与 4 区；点击页面或导航项后关闭。4 区继续独立滚动，不由业务页面重新实现全局壳。

折叠行为由 1 区整体承担：折叠后不压缩内部元素，1 区只保留稳定的折叠按钮；3 区的工作区切换改为按钮，点击后弹出工作区选项。工作区状态由独立上下文 composable 管理，后续业务页面只能消费该上下文，不得自行维护另一份当前工作区。

## 标准组件定义

标准组件是**职责稳定，并且可跨两个或以上页面复用的组件**。它不是目录中的所有组件，也不是给页面专用区块换一个共享名称。

首批标准组件包括 `UiButton`、`UiInput`、`UiDataTable`、`UiList`、`UiDialog`、Toast、`LoadingState`、`EmptyState`、`ErrorState`，以及页面壳、工作区切换器、侧栏导航和页头。

页面专属信息架构、只服务单个业务资源的复杂卡片、只出现一次的组合区块属于页面本地 UI；除非在第二个页面实际复用并提升为共享组件，否则计入非标准 UI 比例。

## 通用前置能力

请求工具统一管理 loading、error、retry 和取消后的状态清理，并绑定当前
WebSocket 资源信封和响应错误分类。算法工具保持纯函数，页面消费统一的
授权快照和工作区上下文。

## 国际化与主题

启动时根据浏览器系统语言自动选择语言：语言标识以 `zh` 开头时使用中文，否则使用英文。每个中文资源键必须在英文资源中存在对应键，结构不一致视为构建错误。颜色、间距、字体、圆角、阴影和状态色由主题令牌集中定义，组件消费令牌或语义化 CSS 变量。

## 当前业务页面

当前页面路由包括登录、概览、用户、Team、权限模板、权限分配、Packages、
Keys、运行状态和 Team 申请。页面通过共享的 `PageHeader`、`RequestState`、
`UiDialog`、`UiButton`、`UiInput`、`UiDataTable`、`UiList`、Toast 和
`LanguagePicker` 组合完成。

## 验收标准

- 页面通过共享组件和当前资源契约组合，不能绕过授权快照、请求状态或 i18n。
- 标准组件不依赖具体页面或业务资源。
- 中英文资源键完全对应。
- 主题令牌集中管理。
- 后续每个业务页面的非标准 UI 使用率低于 25%。
